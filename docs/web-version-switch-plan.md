# 同一入口的稳定版 / 预览版：执行交接方案

> 日期：2026-10-19。状态：规划完成，待其他执行 Agent 实现与验收；不是已上线功能。
> 用户已确认同一网站内切换版本、默认稳定版、初期数据隔离的产品方向。
> 下文给出技术落地方案；交接本文不等于授权部署、迁移生产数据、外发真实项目或 push。

## 1. 本轮交付什么

让用户继续访问原来的私有网站，在页面顶部选择「稳定版 / 预览版」，无需记第二个地址、
重新登录或手动启动进程。稳定版继续日常对话；预览版用于体验已有的主聊、工作群、
委派、追问、回答与结果回传闭环。切换的是正在使用的应用通道，不是即时部署代码。

第一版预览只启用已有合成演示，不接真实 CLI，不读取生产对话、主人上下文或真实项目。
必须持续显示「预览版 · 模拟演示，非真实智能对话 / 真实执行」。现有 demo 会把主聊输入
用于固定委派流程，不能将它包装为已能理解任意自然语言的主 Agent；提供明确的演示操作提示。

本轮不包含：真实模型联调、CLI 隔离补齐、正式任务 Tab、自动学习、记忆接线、生产 schema
迁移、预览数据合并、将预览提升为稳定版，以及通用多版本发布平台。这些工作继续留在原路线图。

## 2. 当前代码事实与改造起点

以下来自本地代码只读核实，不代表检查过当前线上进程：

- `scripts/main-web.ts` 已有稳定版页面、登录、聊天 API 与 SSE；默认监听回环地址的 31415。
- `scripts/main-web-coordination.ts` 已有独立预览组装，但默认是临时目录、临时端口及独立登录。
  它只能显式重开带 `PREVIEW-v2` 标记的私有目录，不能直接作为本方案的常驻 worker 启动器。
- `src/main/web-auth.ts` 将认证保存在数据目录的 `web-auth.json`，同时在进程内持有状态。
  两个进程共用该文件会有陈旧状态和覆盖风险；不能靠共用文件实现统一登录。
- 页面业务请求目前使用根路径 `/api/...`；加按钮而不修改 API 路由，会把预览操作发到稳定版。
- `deploy/agents-master-web.service` 模板指向可变工作树。只分进程、不固定代码产物，
  仍可能在更新和重启时同时改变两个通道。
- 既有 330 项测试和浏览器证据支持的是合成协调预览，不是版本切换或生产部署的验收证据。

## 3. 技术方案：复用稳定入口，增加独立预览 worker

首轮不额外建设第三个网关服务。现有稳定 Web 进程兼任统一认证和窄路由入口；
预览运行在独立进程，通过私有 Unix socket 接入。现有 HTTPS 域名及其转发目标原则上不变。

| 浏览器路径 | 处理方 | 数据与认证 |
| --- | --- | --- |
| `/`、原有 `/api/*` | 稳定入口及稳定运行时 | 原稳定数据；原认证状态 |
| `/api/auth` 及既有登录、退出接口 | 仅稳定入口 | 唯一认证读写者 |
| `/api/versions`（新增、需登录） | 稳定入口 | 仅通道状态、能力与发布标识 |
| `/preview/`、`/preview/api/*` | 入口校验后转发给预览 worker | 独立预览数据；不保存登录状态 |

### 3.1 单一认证权威

保留当前 cookie 名称、根路径作用域与稳定版认证文件格式；已有有效登录应继续可用。
只有入口实例化并修改生产 `MainWebAuth`。worker 不实例化生产认证、不读取认证文件，
也不暴露第二套 setup/login/logout。预览页面登录仍调用根路径认证 API。

入口对预览请求执行与稳定版一致的 session 校验、写请求 Origin/Host 校验、JSON 类型和
请求体大小限制。路径映射采用明确允许列表，未知端点、异常路径编码与越界路径拒绝处理。
禁止用请求参数指定代理目标；禁止以任意转发头绕过现有同源校验。

入口仅通过固定私有 Unix socket 连接 worker；socket 放在服务用户拥有的 0700 目录，
socket 权限限制为 0600。worker 不另开 TCP 旁路。代理不转发浏览器 cookie、Authorization、
密码或客户端自带的内部身份头；内部可信模式只能由专用启动组装启用，不能由 HTTP 参数启用。
worker 的信任依据是该私有传输边界，而不是一个可伪造的 `X-User` 头。

退出登录由入口撤销会话，并立即关闭该会话对应的稳定和预览 SSE；过期会话也要周期校验，
最长不超过现有稳定路径的 30 秒检查间隔。后续 API 返回 401，页面清空私有视图并显示登录。
这不能撤回已发送给浏览器的数据。不得在日志中记录原始 session 或认证请求体。

此方案隔离进程故障、路由和应用数据，并不是对恶意代码的安全沙箱：相同用户的进程以及
同源页面仍有较强互信。只部署经过审查的本项目代码；真实 CLI 的 OS 级隔离门槛不能因此取消。

### 3.2 前端通道与切换行为

- 顶部始终可辨认当前通道，并能切换。根地址默认稳定版；直接访问或刷新 `/preview/` 保持预览。
  两个浏览器标签可分别使用不同通道，不使用全局 cookie 或 localStorage 设置所有标签的当前版本。
- 首轮使用整页导航，避免两套运行时在同一页面内残留。切换前关闭 SSE、停止轮询并使旧请求回调失效。
- 通过显式页面配置传入 `channel`、`businessApiBase`、`authApiBase`、`releaseId`、能力标签。
  配置由服务端可信常量生成；业务请求使用对应前缀，认证请求仍使用根路径。
  不用对整段 HTML 全局替换 `/api` 的方式改造。
- 未发送消息、未提交回答或未保存设置存在时，提示「切换将丢弃未提交内容」；取消则完整保留输入。
  不为此新增持久浏览器私密草稿存储。
- 已提交但尚未确认接收的请求，短暂阻止切换，直至返回或请求超时；超时后明确提示接收状态未知，
  允许用户确认离开。不得自动向另一版本补发。原通道重试仍使用原会话和幂等键。
- 已确认接收的工作继续在原通道后台运行；切换不等于取消。返回后从该通道持久状态重建视图。
- 预览不可用时显示原因和「返回稳定版」，预览业务 API 返回明确 503，绝不能静默转发到稳定数据。
  该兜底页由入口提供，不能依赖已经宕机的 worker。
- 未登录直接打开预览时，统一登录后返回允许列表中的预览路径，禁止任意外部 return URL。
- 页面、历史、状态和 SSE 保持不缓存与原安全响应头要求；不引入跨版本 service worker 缓存。

通道名、应用发布标识、数据库 schema 版本分别展示/记录，不能把 `PREVIEW-v2` 当成产品发布版本。
`/api/versions` 不返回私有路径、环境变量、cookie 或用户内容；预览健康检查必须有界，
不能让稳定页面启动或请求等待 worker 无限响应。

### 3.3 持久数据与单实例约束

稳定数据目录保持原样。预览使用显式指定、仓库外的持久私有目录，例如稳定目录的独立兄弟目录；
数据库、owner context、事件、任务、outbox 与产物均不得和稳定版共用或隐式复制。
统一认证是入口服务提供的功能，不是两个业务目录共用认证文件。

预览服务首次创建目录与重开目录必须是显式不同操作。重开只接受兼容的预览标记/schema，
不兼容就退出并报告，不删除、不重建、不自动迁移。异常清理不能删除已有持久数据。
第一轮 owner context 保持空白或合成内容，不自动从稳定版导入用户信息。

在打开数据库、恢复运行之前取得该数据目录的跨进程独占锁；第二个 worker 必须拒绝启动，
不能仅依赖端口冲突。崩溃后的锁恢复须验证原进程已退出；不能盲删正在使用的 socket。
重启仍遵守已有 unknown/interrupted 语义，不自动重放副作用，也不宣称恢复所有内存工具协议。

### 3.4 发布与故障边界

稳定入口与预览 worker 分别固定到不可变发布目录或构建产物；数据目录不放在发布目录内。
更新预览只切换预览产物和重启预览服务，不能顺手更新稳定入口使用的模块。
两者可来自同一仓库，不要求不同分支，也不建设任意版本数量的管理系统。

工作树当前存在未提交和未跟踪实现。执行者必须冻结批准的源码清单与哈希，不能假定
`git archive HEAD` 已包含待交付功能；也不能把整个工作树连同 `.env`、会话和产物复制发布。
依赖产物同样固定，禁止两个通道共用会随安装改变的运行依赖目录。

预览 worker 崩溃不终止稳定进程。统一入口自身仍是共同故障点，本轮不承诺高可用或零停机。
首次加入切换能力需要更新稳定入口，可能有短暂重启；「保留稳定版」不等于入口代码完全不变。

## 4. 执行顺序与文件范围

执行者先读本文、`AGENTS.md`、现有协调切片规格与验收记录，再实施；无需重新征询已确认的产品方向。
按仓库规范安排独立 CLI 实现与复核，保留脱敏证据。外部模型接收源码的授权范围须在该执行轮确认，
不能把历史某一轮限定授权当作永久授权。

### 步骤 A：冻结基线，拆出可复用 worker

1. 只读确认机器、工作树和实际服务配置；列明已有改动，禁止清理或覆盖其他 Agent 的工作。
2. 从 `scripts/main-web-coordination.ts` 分离协调运行时/业务 handler 与认证/监听组装。
   增加专用 worker 启动入口、固定私有 socket、显式持久目录和单实例锁。
3. 保持原有独立合成演示入口可用；内部 worker 则不创建第二个认证实例。
   不把预览 schema 注入稳定运行时，不改变现有主聊天默认启动语义。

### 步骤 B：入口路由与页面切换

1. 在 `scripts/main-web.ts` 接入默认关闭的预览配置；新增窄路由代理与元数据接口。
   代理、通道配置等可抽成小模块，不继续堆积页面字符串替换或引入完整前端重写。
2. 调整 `src/main/coordination/web-page.ts` 及稳定页面的显式 API 配置、导航和不可用页。
3. `src/main/web-auth.ts` 如需解耦，只调整接口/组装，不借机改密码或 session 持久格式。
4. SSE 必须增量转发，不能缓冲到流结束；下游断开时释放上游，正常长连接不受普通请求超时误杀。
   认证失效、请求错误、worker 退出和重启均有明确终止/重连行为。

### 步骤 C：常驻配置与独立验收

1. 提供独立预览 service 模板、稳定入口可选配置及运行手册，使用最小环境变量允许列表。
   模拟 worker 不加载 `.env` 或模型凭据；不无条件继承宿主全部环境。
2. 测试一律使用临时私有目录、合成用户和假模型；实际浏览器验证完整切换闭环。
3. 独立复核者对冻结源码重跑检查，分别列出通过、未覆盖和阻塞项。未过下表验收不得标记可部署。
4. 到这里交付源码、配置模板、报告和部署清单；不自动安装服务、重启现网、commit 或 push。

## 5. 验收标准

| 验证项 | 必须观测到的结果 |
| --- | --- |
| 旧入口回归 | 根地址仍是稳定版，既有登录状态可用，聊天/历史/设置行为不变 |
| 同站切换 | 一次登录访问两通道；刷新预览不跳稳定；不需要第二个端口或密码 |
| 数据隔离 | 两侧写入不同合成标记，历史、owner context、问题、任务、事件互不出现；目录分别核验 |
| 完整路由 | 枚举页面实际调用的全部 API，包括历史、设置、恢复、控制和 SSE；预览无根路径业务请求遗漏 |
| 并行标签 | 两标签不同通道独立工作；相同会话 ID/请求 ID 不串数据、不跨通道去重 |
| 输入与未决提交 | 草稿切换提示可取消；提交超时明确未知，不跨版本自动重发或丢失幂等键 |
| 后台持续 | 发起合成任务后切回稳定聊天，返回预览仍可看到进展、回答问题和接收结果 |
| 故障降级 | 停止 worker 后稳定仍可用；预览显示可返回的 503 页面，绝不读取稳定历史冒充预览 |
| 持久重启 | 同一预览目录重启保留历史；运行状态按既有规则恢复为 unknown/interrupted，不自动重放 |
| 单实例 | 第二个 worker 在打开/恢复该目录前失败，不干扰原进程或删除其 socket |
| 认证边界 | 未授权 API/SSE 拒绝；伪造内部头、路径编码、跨源写请求不能绕过；worker 无 TCP 旁路 |
| 退出与过期 | 退出后两通道流关闭、后续请求 401；过期在约定间隔内生效，不再发送私有事件 |
| 流式与资源 | SSE 事件及时到达；浏览器断开释放上游；预览异常不会拖挂稳定请求 |
| 发布隔离 | 更新/重启预览后稳定发布标识、依赖与数据不变；不依赖可变工作树启动 |
| 范围与保密 | 清楚显示模拟能力；无真实模型/CLI 调用；日志、页面配置与发布包无密钥或生产内容 |

验收报告附具体命令、版本/哈希、测试结果、真实浏览器步骤与脱敏证据位置。
全量测试和 typecheck 也需通过；既有 330 项是历史基线，不是可代替本轮新增验收的数字门槛。
不能只检查首页 HTTP 200，或仅凭截图声称整个交互闭环可用。

## 6. 部署审批、上线与回退

实施验收完成后，由执行者向用户单独提交上线申请，说明确切服务、代码/数据路径、
备份方法、预计中断、回退步骤及仍未覆盖的风险。用户批准之前保持现网不动。

获批后的顺序：

1. 核实真实运行配置与旧发布基线，保存私有配置备份；涉及 SQLite 时使用一致性备份，
   或停写后正确处理 WAL，不能只复制运行中主数据库文件。备份不得进入 git 或模型 prompt。
2. 安装独立预览产物和私有数据/socket 目录，先验证 worker；再更新入口，预览开关先关闭。
3. 验证原登录和稳定路径后启用预览，执行批准的合成流程。生产内容检查和真实模型调用
   不隐含包含在合成验收中。既有 Tailscale 转发原则上保持原状，不开放公网端口或 Funnel。
4. 交付用户仍然使用的入口、切换位置、模拟能力说明和回退操作，不要求用户记内部 socket/端口。

预览异常时先关闭预览入口并保留可返回页面，再按有界停机流程停止 worker，保留预览数据。
必要时回退稳定入口代码；本轮不改生产 schema，仍须验证旧发布兼容性，不能靠删库回退。
切回稳定版不会撤销已发生的操作；将来预览转正及数据合并另出迁移方案、另行授权。

## 7. 交接完成的定义

执行 Agent 应交回：实现改动清单、固定发布标识、配置模板与操作手册、独立复核报告、
验收证据、待用户批准的部署清单。只有部署获批且浏览器验收完成，才能标记「版本切换已交付」。

本规划轮只写文档；用户将方案交给其他 Agent 执行。版本入口完成后，回到工作项目 Agent 主线：
补齐真实模型接线证据和完整执行隔离，再讨论批准项目的真实使用，不把版本管理本身变成产品主线。
