# 通用个人 Agent：产品发现稿 v0

> 状态：探索中。本文记录已经由用户确认的产品原则和首批待验证场景；它不是技术方案、
> 实现计划或功能承诺。
>
> 最近更新：2026-09-10。

## 1. 产品命题（已确认）

做一个由用户自己定义、长期存在的个人 Agent 系统。

- 用户始终从一个主 Agent 进入，并可以无限、自然地对话；主入口不应被任何长任务占住。
- 主 Agent 的主要价值是理解用户、持续维护上下文、判断和协调；重执行可由后台子 Agent
  完成。
- 对话不是任务的容器。用户委托的事务必须能独立持续、暂停、恢复、拆分、取消，并在用户
  转换话题后继续推进。
- 子 Agent 是内部实现手段，不是用户必须管理的一组 Bot。
- 产品自建、产品定义权在用户手中；OpenClaw、Hermes、Muse、Grok Bot 只作为体验和实现
  的参考，不作为产品替代或上游边界。

## 2. 当前范围（已确认）

首批只服务三个持续上下文：

1. **人际关系**：重要的人、承诺、互动脉络、合适的跟进时机。
2. **工作项目**：目标、协作、进展、阻塞、待决事项和交付。
3. **长期目标**：方向、现实进度、阶段性选择、调整与复盘。

当前明确不做：健康、家庭/居住、消费、旅行等其他生活领域。它们可在前三条主线跑顺后
再讨论，不能以“万能助手”为由提前膨胀范围。

## 3. 不可妥协的体验原则（已确认）

### 入口永远可用

用户可以在后台工作进行时随时提问、换话题、补充事实、改变优先级或要求停止。用户的新指令
优先于后台工作；已发生的外部动作另行如实呈现，不能假装能撤回。

### 事务持续，但不骚扰

系统应该在状态变化、风险、交付或真正需要用户判断时回来，而不是用频繁的进度消息占据
注意力。用户可定义希望被打扰的程度。

### 记忆可见、可纠正、可忘记

系统对人、项目、目标和偏好的长期认识必须能追溯来源，并允许用户查看、纠正、删除或要求
遗忘；不能把关键判断藏在不可见的聊天摘要中。

### 外部后果必须有边界

系统可先阅读、整理、起草、建议和准备；未经明确授权不得代表用户联络他人、作出承诺、
发布内容、消费、删除或改变外部系统。授权应针对具体动作及范围，而不是一句泛化的聊天许可。

## 4. 首批场景假设（待用真实生活校准）

这些不是已决定的功能，而是用来观察用户是否愿意长期托付的最小故事。每条都必须验证：
系统知道什么、后台做什么、何时打扰、什么必须停下询问。

### A. 人际关系：承诺的可靠守护

用户随口说：“我答应周末帮朋友看一份东西。”

- 系统识别这不是即时问答，而是一项对人的承诺；记录对象、事情、时间线和不确定处。
- 到合适时间先向用户确认这项承诺是否仍有效、是否已完成；不直接替用户联系朋友。
- 用户更新事实后，系统更新该关系上下文，避免以后重复提醒或忘记。

**待验证点**：什么才是“合适时间”；怎样提醒才像可靠的助手而非待办软件。

### B. 工作项目：用户不再充当信息搬运工

用户说：“这个项目这周要推进。”

- 主 Agent 将其维持为独立工作流，整理目标、当前事实、协作方、阻塞和待决项。
- 它可以让后台 Agent 调研、执行或核验，并保留原始证据与交接记录。
- 用户中途讨论无关话题时，主入口立刻响应，项目仍在后台推进。
- 主 Agent 仅在优先级冲突、范围变更、外部动作、风险或交付点请求用户判断。

**待验证点**：用户是否能在不反复追问的前提下掌握真实状态，并确信系统没有自作主张。

### C. 长期目标：适应现实而非机械催促

用户说：“我希望在半年内完成一个重要方向。”

- 系统先理解目标为何重要、有哪些约束和模糊处，而不立即生成僵硬的每日计划。
- 它把工作项目、承诺和时间变化作为现实信号，持续判断目标是否在推进、漂移或已不再适合。
- 它在需要选择、复盘或调整时提出有依据的建议；用户可暂停、修改或结束目标。

**待验证点**：系统如何做到有帮助但不说教；什么证据足以支持“该调整目标”的建议。

## 5. 下一轮产品发现（尚未开始）

按场景逐条收集真实交互，而非先设计架构：

1. 用户给出每条主线中最真实的一至两个近期例子。
2. 为每个例子写出从交代事务到完成/暂停的完整时间线。
3. 标注每一个“系统可自行做 / 必须汇报 / 必须先问”的节点。
4. 记录用户觉得有价值、打扰、越界或不可信的瞬间。
5. 只有跨案例反复出现的能力，才进入后续产品能力模型与技术设计。

## 6. 参考产品的边界

- Muse：借鉴长期后台工作、上下文随现实变化而调整、敏感动作单独审批的体验。
- Grok Bot：借鉴持久角色、可见交接、从一次成功任务沉淀为 routine 的方式。
- OpenClaw / Hermes：借鉴自托管 gateway、记忆、技能、后台任务和多 Agent 的实现经验。

不应照搬：任何上游项目对 workspace、Bot roster、配置文件或渠道路由的产品中心性。它们是
实现候选，不应反向定义本产品的用户体验。
