# 主 Agent 记忆闭环修复方案

日期：2026-10-24。状态：供下一轮实现使用的短方案，尚未实现或验收；本文件不代表已安排 CLI，也不授权部署或改写现网记忆。

2026-10-24 补充：用户确认采用下述墓碑实现与时序边界；不改写旧聊天，不另开架构设计。

## 目标与问题

让用户通过正常对话询问、确认、纠正和忘记记忆，得到与真实存储一致的答复。

已核实：已确认记忆实际进入了主 Agent 的系统上下文，但它仍自称没有读取权限；
现有工具只支持提议，不能查询状态或执行纠正；用户纠正之后，旧记录仍可能与新记录同时生效。
这是现有记忆切片的收尾，不是新建长期记忆平台。依据 `product-discovery-v0.md` 的
“记忆可见、可纠正、可忘记”与“已有明确授权时直接推进”原则。

本文只使用合成示例，不收录用户实际对话或私人记忆。

## 本轮交付

### 1. 让管家能核对自己记住了什么

- 在主对话提供非终止记忆查询工具 `read_memories`：返回记录 ID、内容、状态、来源标识、
  更新时间；默认返回待确认与当前有效记录。只访问本预览用户的数据，不向工作群注入私人记忆。
- “你记住了什么”“刚才确认成功了吗”等状态问题以查询结果为准；已注入的有效记忆仍可直接
  用于日常交流，不要求每轮重复查询。
- 工具/提示词明确说明：记忆保存在本应用的私有数据目录，用户可在设置中的记忆列表查看；
  已确认内容会供后续主对话使用。没有通用文件访问能力不等于无法读取应用提供的记忆。

### 2. 明确纠正和忘记要真正落库

- 在主对话增加受限管理工具 `manage_memory`，支持 confirm/correct/forget 操作，
  用记录 ID 操作，复用现有存储和界面接口的业务逻辑。具体函数拆分由实现者决定。
- 用户明确说“确认这条”“把那条改成……”“忘记刚才的测试记录”时执行对应操作，
  不再要求重复点一次确认。目标不清才询问；普通讨论、假设和模型推测不能作为修改授权。
- 自发提议的新事实继续走现有 pending → 用户确认流程，不扩为自动记忆。
- 纠正作为一次完整操作：旧记录不再有效，新内容成为当前事实，保留必要的旧记录、关联关系、
  变更时间和用户指令来源。不能只追加一条互相矛盾的新记忆。
- 采用墓碑记录：forget 将旧记录标为 `forgotten`，correct 将旧记录标为 `superseded`，
  新记录通过 `supersedes` 关联旧记录；保留原内容、变更时间与来源供追溯，不物理删除或改写旧聊天。
- 忘记使该记录停止作为用户事实使用；界面明确叫“忘记/不再使用”，不冒充删除原始聊天。
  原始聊天清空及完整证据级删除沿用各自边界，本轮不扩大为跨系统删除。
- 界面按钮与对话工具得到相同结果；旧文件可继续读取，既有确认记忆不能丢失。
- 同一 ID 重复 confirm/forget 返回真实当前状态，不重复写入，也不能把不适用的状态说成操作成功。
  correct 同样要求幂等：同一次纠正重试必须返回同一条新记录，不能再次生成替代记录。
  仅有 `supersedes` 关联不足以保证幂等；操作标识由宿主绑定到这次用户指令，具体存储方式由实现者决定。

### 3. 状态、上下文和管家说法一致

- 操作结果返回实际成功/失败、受影响记录及最终状态。只有成功后才能说“已确认/已修改/已忘记”；
  拒绝或写入失败必须如实说明，不能用自然语言答应代替操作。
- 更新后立即刷新可供后续模型调用使用的记忆状态；同一回合后续答复以工具结果为准，
  下一回合及重启后以当前有效记录为准。不得继续注入已作废记录作为当前事实。
- 墓碑记录不进入当前有效记忆列表；默认查询仍只返回待确认与当前有效记录。
  纠正时可提供明确替代关系，涉及相关旧历史或旧回合状态时再提供必要的失效说明。
  不把所有已忘记内容永久全文注入每轮 prompt，也不改写或清空整段聊天；本轮不要求复杂语义过滤、
  向量库或通用依赖图。
- 系统上下文中的失效声明只作辅助，不能作为唯一保证。同一旧来源触发的重复提议由存储逻辑
  拦截，不能仅靠提示词防止恢复。用户后来新的明确表达允许重新确认，不把失效标记变成永久禁令。
- 查询与写入的事件来源由宿主绑定，不能让模型伪造用户指令来源；重试/恢复同一次操作不能
  重复修改或产生多条替代记忆。现有记忆为 JSON 文件，不能假定外层 SQLite 回滚会撤销文件写入。

**界面确认的时序边界：** 对话工具确认后，同回合后续答复以返回结果为准；用户在界面点击确认时，
不要求改写已经生成的回复，也不要求抢占正在运行的回合。但确认成功后用户再发起的新回合，
必须能读取最新状态，不能继续声称“待确认”或“没有读取权限”。后者是本轮必修问题，不列为残余行为。

## Prompt 怎么调整

当前预览 prompt 由 `scripts/coordination-preview-runtime.ts:previewCheckpoint` 与
`src/main/coordination/model-host.ts` 拼装。只在这条实际运行路径补齐记忆能力、状态和
操作结果约束；工具未实现之前不能先宣称具备能力。

静态规则可小范围收拢到清晰的函数/模块，主人背景与记忆继续动态注入。不要单独开展
prompt 平台重构，也不要把稳定版 `foreground.ts` 的不同能力说明直接照搬进来。

## 验收：用用户真的会说的话走一遍

使用合成信息，例如“我喜欢蓝色”，避免复制私人记录进测试：

1. 提议 → 确认 → 问“你记住了什么、放在哪里”：对话确认与界面确认两条路径分别覆盖，
   确认成功后新回合答复与实际记录一致，不再声称待确认或无法读取。
2. 说“刚才是测试，把蓝色改为绿色”：旧记录失效、新记录有效；保留包含旧事实的聊天历史，
   再询问、重新打开及重启后都不并列两条当前事实。
3. 说“忘记这条”：有效列表与后续背景移除；保留旧聊天、重新打开或重启后都不自动恢复。
4. 指代不清时澄清，纯讨论不修改；同一次 correct 重试仍只有一条替代记录，confirm/forget 重试
   返回真实状态；旧来源重提被拦截，用户新的明确表达可重新确认；写入失败不谎报成功。
5. 界面与对话状态一致；主聊天、工作群任务、版本切换的既有行为不退化。

存储/回合边界用定向测试，用户流程用 Chromium；至少一次合成内容的真实模型对话验证
“已确认却自称待确认/无读取权限”的原始体验问题，并覆盖保留旧聊天后的纠正与忘记。
检查点包含失效段只是结构测试，不能代替行为验收。真实模型结果与离线测试证据分别报告。
通过 typecheck、相关测试与全量回归后，由 Codex 做定点独立复核，不重复扩展完整架构审查。
