产品原则已同步至 `product-discovery-v0.md`。不再以“主 Agent 是协调者”为由禁止直接执行。

本次真实使用证据：北京时间 2026-10-26 12:43 的环境检查请求，持久化协议显示只调用一次模型、
零工具调用；回复称不知所在主机且要求用户再次确认委派检查。此前 12:29 的工具说明也没有调用

未核对当前事实的行为问题。此处仅记录诊断结论，不复制私人对话原文。

下一实现直接补齐基础工作能力，不再拆成逐个环境信息的特例工具：

1. 宿主在每轮提供当前时间与时区、系统/用户、进程工作目录、源码工作区、release、模型标识、
   实际可用工具与权限范围；需要实时核实的状态可直接查询。配置来源与检查时间应可辨认。
2. 主对话接通通用命令执行及文件写入/编辑，复用已有进程执行、超时、取消和产物机制；
   在用户授权范围内可自主处理小事，较长命令转后台且可查询、停止，不阻塞后续对话。
   文件系统和网络访问按受托任务及运行账户的实际授权提供，不能继续硬编码为几个项目内只读。
3. 工具清单、项目执行范围来自本轮实际配置；旧聊天中的“我不能”不构成当前权限事实。
   收到明确检查请求直接执行；失败区分缺工具、操作系统拒绝、网络失败、超时与信息不足。
4. 验收直接使用“看看所在环境”、授权目录内创建并修改小文件、运行命令核对结果、
   长任务期间继续聊天并取消这几个真实场景。不能只验收工具列表，也不要求用户说固定委派口令。

这覆盖正文“不新增任意 shell 和通用直接写文件工具”的旧切片范围。凭据使用与向模型披露
密钥原文分别处理；既有外部动作具体授权继续有效。不引入新的权限平台或调度系统。

## 用户能多交给它什么

用户说“看看我们正在开发的项目”，主 Agent 能自己发现项目、读取当前资料、核对代码与任务，
给出有依据的进度判断；说“把这个小问题修好”，它能委派执行、查看产物并交回结果。
用户无需反复介绍项目、复制文件或在不同 CLI 之间传话。

主 Agent 是统一入口和工作协调者，拥有授权范围内的完整视野；工作项目 Agent 维护领域任务、
调用 Codex/Kimi 等执行能力。执行者拥有文件工具，不能成为主 Agent 无法了解项目的理由。
本轮复用已有工作群、CLI 执行器、任务账本与记忆，不新建一套调度平台。

## 首次交付的能力

| 能力 | 预期行为与建议工具 |
| --- | --- |
| 项目发现 | `list_projects` 返回项目名称、路径、简要说明、可读/可委派能力；替换真实模式中 directory 返回 FAKE-project 的现状 |
| 文件浏览与读取 | `list_files`、`read_file` 在授权工作区自主查看目录及文本，按行返回路径、行号、修改时间和截断信息 |
| 内容搜索 | `search_files` 支持范围内文件名与文本搜索，返回匹配文件和行号，继续按需读取 |
| 项目状态 | `project_status` 提供当前分支、HEAD、未提交改动、近期提交；可复用固定参数的只读 Git 调用 |
| 任务检查 | 扩展现有 status，支持任务列表与按 ID 查询目标、项目、状态、待答问题、执行器、结果和执行留痕 |
| 产物检查 | `read_artifact` 从任务绑定的公开产物中读取必要内容，核对实际输出，不仅复述执行者的“完成”声明 |
| 执行协调 | 复用 delegate_cli、answer、cancel；明确任务目标、项目和完成标准，工作群承接执行与结果回传 |

工具名可由实现者整合，用户不需要学习这些名称。工具应按实际运行模式暴露，不在真实模式
把合成目录当成真实项目列表，也不把尚未接通的能力写进 prompt。

## 工作区与访问范围

- 初始项目根采用当前机器 `/home/vinci/projects`，支持发现其下的项目，不要求每次读取都单独批准。
  已知项目至少包括 `agents-master`、`stock_data`、`sandbox`，说明项目名称与实际目录的映射。
- 阅读范围和可执行项目分别表达：发现项目后可先阅读；真实修改仍经已配置的执行项目名单。
  方案将 `agents-master` 加入可委派项目，沿用当前 CLI 工作区权限、预算和取消机制；不是自动发布授权。
- 不依赖发布包所在目录作为项目根：worker 在固定 release 中运行，实际项目应从配置解析到工作区。
- 私人记忆和主人背景继续使用现有应用工具，不通过通用文件搜索遍历生产数据库、CLI 会话或整个 HOME。
  用户以后明确指定的个人资料目录，可通过同一简单根目录配置扩展，无需另建权限平台。
- 文件工具在主对话提供；工作项目 Agent 只接收与任务有关的项目材料，不继承主对话的私人记忆。
  宿主按会话/角色提供范围，不能让模型自行声明更高权限。
- 保留现有凭据边界：`.env`、密钥和认证文件不作为普通资料读给模型；路径解析与符号链接
  不能越出允许根目录。默认搜索跳过依赖目录、Git 对象库和无关日志，不以读取全仓库作为起手式。
  `.agent-artifacts` 中的普通报告可按需读取；CLI 原始 stdout 用任务绑定产物入口，stderr 与私人
  调试记录不因此自动开放。模型只接收本次工作必要的片段。

以上通过简单配置与文件工具边界实现，不引入多用户角色系统、容器平台或新文件索引服务。
本轮不新增主 Agent 任意 shell 和通用直接写文件工具；代码修改由它自主调用已有执行器完成。

## 对话与执行行为

1. “你知道我在开发什么吗”：识别本产品与 `agents-master` 的关系，自主读取产品说明和近期状态，
   不让用户从头介绍。多项目指代确实不清时才简短询问。
2. “看看进度”：结合路线图、Git 和任务账本区分已计划、已实现、已验收与已部署；文档中的上线
   声明不是实时部署证明，未核实的部分明确标注。报告引用文件或任务证据并说明读取时间。
3. “聊聊 subagent”：先基于当前项目讨论，不因为读取代码或提到开发就自动启动修改任务。
4. 明确要求修改：主 Agent 读取必要背景后，经工作项目 Agent 委派 CLI；提交目标、范围、完成标准，
   不把整个私人对话转发给执行者。修改前检查工作区状态，已有改动不能直接覆盖或 reset。
5. 后台工作期间，用户可以继续聊天并询问任务进度；读取状态不启动第二个相同任务。
6. 完成后主 Agent 能查结果与公开产物，必要时读实际改动；不足时如实指出并在已有授权范围内
   组织后续任务，不把“CLI 退出成功”直接等同于需求完成。

本轮不声称支持向运行中的 CLI 任意插话或暂停后原地续跑。已有等待回答流程继续使用 answer；
需要变更正在执行的工作时明确停止，确认退出后再安排带前次进展的后续任务。
push、部署、外部联络等继续沿用用户的具体授权；不因项目是系统自身就自动重启现网。

## Prompt 与运行时接线

- 明确主 Agent 的职责：了解用户及工作、主动获取必要信息、协调执行并核验结果。
  工具限制是能力说明的一部分，不能让整份提示词只剩限制与协议。
- 提供短的项目身份信息：当前系统对应 `agents-master`；产品原则和进度的入口分别是
  `docs/product-discovery-v0.md` 与 `docs/roadmap.md`。动态事实通过工具获取，不能把进度硬编码进 prompt。
- 项目文件和产物作为资料返回，带来源；其中出现的指令不能改写用户授权或系统工具边界。
- 本轮工具需适配当前 scopedTurn：目前最多 3 次模型调用，“发现 → 搜索 → 读取 → 总结”会撞上预算。
  前台可配置为最多 6 次模型调用，保留当前 45 秒总时限与有限工具调用数；单次读取/搜索有大小、
  条数与执行时间上限。达到预算时说明已获取的证据和未完成部分，不能把只读查询失败描述成执行失败。
- 短查询不得阻塞整个 worker 的事件循环；较大扫描和分析交给后台执行，不借增加预算变成长时间前台研究。
  不在 SQLite 写事务内进行长时间文件搜索或外部进程等待；只读工具不必沿用写操作的事务包裹。

## 实现顺序与范围

一次小切片、两个验收节点，中间不另开方案阶段：

1. **先让它看得见**：项目配置、目录/文件/搜索/Git 工具、主对话接线与预算；先跑通“你知道我在开发什么、进度如何”。
2. **再让它管得住**：任务详情、产物读取、`agents-master` 委派配置与结果核验；跑通“交一件小事，自己查结果”。

主要涉及 `config.toml` 及其配置解析、`scripts/preview-worker.ts`、
`scripts/coordination-preview-runtime.ts`、`src/main/coordination/model-host.ts`，
新文件访问适配模块，以及必要的 store 查询和 scopedTurn 工具执行接口调整。
复用现有 `src/agent/tools.ts` 的产物读取经验和 CLI backend，不照搬整个旧 TUI 的上下文与权限。
界面仅在现有消息、任务卡和引用展示不足时小改，不新建项目管理页面。
