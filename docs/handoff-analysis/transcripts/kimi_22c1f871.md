## 1. XBRL 允许同一份年报里同一个"概念"被标记多次

公司提交 10-K 时，报表里的每一行数字都要打上机器可读的 tag。但一份年报里"成本"出现在**多个不同的报表/附注**里，每次出现都可以独立打 tag:

- 合并利润表里的"销售成本"447.52 亿——这是正式的合并数字；
- 分部附注的调节表里"方法论差异"4,900 万——这是把分部口径调成合并口径时的调节项。

CAT 的会计师给调节行也打了 `CostOfGoodsAndServicesSold` 这个 tag——从 XBRL 规则看这并不违规（tag 描述的是"已售商品和服务成本"这个概念，调节行确实也涉及成本），但它**不是**利润表上的那个合并成本。于是同一份 filing、同一个期间、同一个单位下，同一个"成本"语义出现了两个数值完全不同的合法事实。

为什么各公司用法还不一样？因为 US-GAAP taxonomy 给了好几个意思相近的成本 tag(`CostOfRevenue`、`CostOfGoodsAndServicesSold`、`CostOfGoodsSold`),SEC 不强制用哪个，各公司审计师有自己的习惯：CAT 用 CostOfRevenue 当合并行，ITW 可能反过来。而且同一家公司过几年还可能换 tag(tag migration)。所以"哪个 tag 是合并行"**因公司而异、甚至因年份而异**，这就是通用规则必然失败的根本原因。

## 2. SEC companyfacts API 收录时丢掉了"这行数字出自哪张表"的信息

XBRL 原文里其实有 context（这个数属于合并报表还是某个分部）和 presentation 结构（这行数字在哪张表的第几行）。但我们的数据源是 SEC 的 companyfacts 汇总接口，它有两个特性直接造成现在的局面：

- **只收录无维度（undimensioned）的事实**。带分部维度的事实（"工程机械分部的成本"）根本不会出现在接口里——所以 NEE、PR、FANG 那种"主 capex 行按分部/自定义行披露"的公司，接口里直接查无此数，这也是 #5 那批 exception 的来源；
- **保留 tag 但抹掉表格结构**。接口告诉你"这家公司有这个 tag 的这个值"，但不告诉你它出自利润表还是附注调节表。CAT 的 4,900 万和 447.52 亿在接口里是两条平起平坐的事实，看不出一个是正表、一个是附注调节项。

## 3. 我们的管道在"多候选"时没有裁判规则

版本层 ingest 把这些事实原样收进来（这本身是对的，原始事实不能丢）。但到选取环节：

- selector 对 COGS **没有设 canonical 优先级**（收入有，成本没有），两个 tag 的事实全部透传；
- projection 按（股票， 年度）透视时，同一个字段遇到两个值就是**后写覆盖先写**——哪个赢取决于查询返回顺序，本质上是随机的。CAT 就是因此被 4,900 万覆盖出了 99.9% 的毛利率。

## 4. 那 80 行"单候选也是子项"又是另一回事

这类公司（LCID、VICI、NBIX 等）在 companyfacts 里只有一个成本 tag，没有竞争对手——但那个 tag 的口径天生就窄。比如 REIT 的成本 tag 可能只含物业运营直接成本，生物科技公司的成本 tag 只含产品销售成本、不含研发。这不是"挑错了"，而是**公司披露的成本概念和"毛利 = 收入 − 销售成本"的会计等式不匹配**。没有第二个值可以比，所以冲突检测天然失效，只能用合理性审查（和行业水平、和收入规模比对）来识别。
