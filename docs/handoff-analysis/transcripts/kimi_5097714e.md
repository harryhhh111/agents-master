### 3. 失败 ingest run 无法可靠落库

1. `run_id = None`；
2. 数据事务失败后先 rollback；

5. 增加真实 SQL 失败集成测试。

### 4. 同批重复和并发写入尚未正确计数

当前流程是：

```text
先查询已有事实
→ 在 Python 中分类
→ INSERT ... ON CONFLICT DO NOTHING
→ facts_inserted = len(new_rows)
```

同一个输入批次内若出现相同唯一键，或者两个任务并发解析同一 snapshot：

- 两边都可能认为记录是 new；
- 实际只有一边成功插入；
- `facts_inserted` 会被高估；
- 并发异值可能被 `DO NOTHING` 吞掉，未进入 conflict。

应使用数据库返回值作为真实计数，例如：

```sql
INSERT ...
ON CONFLICT ...
RETURNING fact_version_id
```

同批次先按唯一键分组，比较 `value_hash`；生产环境再增加 advisory lock、snapshot/run 幂等键或原子 upsert/conflict 函数。

::code-comment{title="[P1] 插入计数与并发冲突不可靠" body="existing 查询与 INSERT 之间存在竞争窗口，且同批重复未先归并。`len(new_rows)` 不等于实际插入数，并发异值可能被 DO NOTHING 吞掉。应基于 RETURNING 计数，并对同批键归并或对 snapshot ingest 加锁。" file="/home/vinci/projects/stock_data/core/fetchers/us_financial.py" start=1253 end=1340 priority=1}
