# 第一轮 Agent 接入预检：归档与后续边界

日期：2026-10-16。这是四份预检/复核报告的脱敏整理版，不替换私有原件，不把旧报告的
人工解释冒充自动测试结果。原件位于 `.agent-artifacts/prechecks-2026-10-15/`，保持不变。
原始会话、认证引用、个人数据不进入 git。

## 结论与本轮选择

- 模型侧：当前组合的**候选工具扩展具有可行性**；不是现有 FrontBrain 全链路验收通过。
- 执行侧：三个现有 backend **均未通过完整接入门槛**。Codex 是优先复验候选，不是已批准的生产执行器。
- 用户同意沿 A 路线推进：先修复预检方法，再做合成输入的最小 OS 文件视图隔离原型及交叉复核。
  能复用原生隔离能力就先验证，不预先承诺自研完整沙箱。
- 会话/状态/迁移规格可继续细化，假执行器可先验证业务闭环；真实执行接线仍需完整权限门槛。
- 本轮不迁移生产数据库、不读取真实 `stock_data` 内容、不部署、不 commit/push。

## 1. 模型协议报告（Kimi 执行）及勘误

组合：DeepSeek 官方端点、`deepseek-flash`、非流式、`thinking: disabled`、OpenAI Node SDK
7.4.0、SDK `maxRetries: 0`。合成工具只有固定回执，不执行真实委派。

保留的 transcript 有 21 次 SDK 调用尝试：20 个响应、1 次本地超时；不能推定超时没有服务端消耗。
S1 四条工具选择/参数样本符合预期。S2a 展示查询后澄清，S2b 展示 query → delegate → 文本结束，
配对合法。S3 的三条样本是文本拒绝/澄清或合规参数。S4 六条混合闲聊/模糊请求中有一条触发
只读查询，因此 **S4 FAIL 保留**；不是生产误触发率，也不是错误委派的证据。
S5 证明一次本地超时后正常请求恢复，不证明持久幂等或真实任务恢复。

归档时采用以下较窄表述：

- “provider 强制修复”改为“观察到返回参数符合 schema，内部机制未知”。
- 10,112 / 14,880 ≈ 68% 是 provider 上报的 prompt token 加权缓存命中率；没有对照，
  不能将其唯一归因于 system 前缀，也不能推出加速幅度。
- `results.json` 是人工合并及部分重判后的汇总；原始 transcript 是观测依据。
- 缺参数时倾向提问是少量样本，不是可靠行为保证。白名单能挡越界，但挡不住猜中合法值的模糊意图。

## 2. 模型协议独立复核（Codex）

判定：**背书有保留**。独立复核未新增模型探针调用。确认调用数、用量、10 个工具参数校验、
两轮配对及 S4 反例；不背书 provider 内部机制、缓存因果、完整前台能力和全局硬预算。

需要修复的 runner 问题：

1. 调用预算按场景重置，而非整轮共享；失败尝试也必须计数。
2. `all` 清空 transcript，汇总覆盖历史；应每轮创建独占目录，原始证据不可覆盖。
3. S3/S4 在 API 全失败时可能判 PASS；需区分 FAIL、BLOCKED、UNVERIFIED。
4. S2b 未检查预期工具链，S5 未检查工具名；S2a 自动判定与人工解释混在一起。
5. 超时记录遗漏 latency；usage 未获得应为未知，错误文本不能直接裸存。

实际 FrontBrain 尚不传递 `tools`、`tool_calls`、`tool_call_id`；探针直接调用 SDK。
后续必须验证真实适配路径、宿主授权和非法参数拒绝，不能只复制探针的成功样本。

## 3. CLI 隔离报告（Codex 执行）及勘误

组合：本机 Codex 0.161.0、Kimi 2.2.0、Claude Code 2.1.195。测量使用临时 CLI 用户态、
合成项目/假秘密和外层只写保护；不是完整真实 HOME 的默认运行状态。

| 维度 | 有证据支持的结论 |
| --- | --- |
| Codex read-only 拒写 | 所测 shell 直接写和 resume 顺手保存均被阻止；CLI 整体 exit 0 不等于工具成功 |
| Codex 越界读 | start/resume 均能读取 cwd 外四类假秘密；read-only 不等于项目限定读取 |
| Kimi / Claude 写入 | 所测默认 print / acceptEdits 均能写合成输入；Claude 单次跨项目 Read 拒绝不代表 OS 隔离 |
| 环境 | 三个 backend 启动器全量继承父环境；shell 清理对照不覆盖 CLI 父进程、认证文件及 proc |
| MCP | 部分验证：启动、发现、审批拒绝、按 server 禁用有证据；真实用户插件及其他出口未验证 |
| 网络 | Codex 所测 shell 外联失败，有宿主和固定解析对照；不覆盖 MCP、插件、Unix socket 等全部出口 |
| namespace | 本机 user/mount namespace 可用；旧 write_guard 只约束写入，不能当作安全文件视图 |

原始启动账本共 10 次（含 resume），其中一次模型已启动后发生工具沙箱初始化失败，随后重跑一次。
不是“没有任何重试”。直接写回执明确含 errno 30；resume bash 回执只有只读文件系统文本和 exit 1。
真实敏感文件未用作探针，不能声称已泄漏真实凭据。

六项 P0 保持：批准输入的 OS 文件视图、宿主 env 白名单、执行前能力校验并拒绝不满足的组合、
输入外的私有状态/产物、独立配置与受控扩展/网络、session 与 backend/project/input/policy 的绑定。
必须在实际宿主接线中成立，孤立脚本通过不能代替这些修改。

## 5. 数据边界与下一道验收门

当前只用合成数据。进入真实项目之前需确认“允许的文件内容 × 实际接收服务”：

- 领域判断的 DeepSeek 与执行 CLI 使用的模型服务是两个接收方；批准前者不自动批准后者。
- 当前候选 Codex 沿用用户配置的服务，不静默切换 provider/model。
- 建议源码与必要文档按清单筛选；凭据、个人原始对话、财务/私人文件默认排除。
  **这是待确认的真实数据策略，不是本轮对真实内容的外发授权。**
- 文件类型黑名单不充分；需冻结清单、内容摘要、拒绝越界链接、检查配置/指令携带的数据，
  不运行项目脚本，不随扫描自动扩大允许范围。

原型验收至少包括：允许读取正对照、越界及符号链接拒读、拒写、网络正反对照、环境白名单、
私有产物目录和缺能力拒绝。工具子进程沙箱与整个 CLI 进程安全是不同边界；实际模型认证、
扩展加载、新建/续接和宿主适配器路径必须另行复验。

本轮补查：[Codex 官方权限说明](https://learn.chatgpt.com/docs/permissions)提供命名权限配置，
支持最小运行依赖与明确文件根的组合；本机 `codex sandbox --help` 也提供 `-P`。
官方同时说明其与旧 `sandbox_mode` / `--sandbox` 不可混用，后者可能改变配置生效路径。
因此先验证原生命名配置，不能只在当前 `-s read-only` 调用上叠加字段后假定生效；
是否满足本机完整边界仍以实际探针为准。

## 7. A 路线原型的实际进展

原型源码：[运行说明](../../scripts/prechecks/cli-isolation/README.md)。
Codex 实现；协调者检查后在获准的外层执行环境复跑。零模型探针调用、没有真实项目输入。

经历三种不同失败后才运行成功，失败原件全部保留：

1. 受限工具环境中，native sandbox 初始化报 socket 目录错误，测试监听器也无法建立；
   这不算拒读/断网通过。
2. 换到获准环境后，抽象 Unix socket 地址为 bytes，探针 JSON 序列化失败；
   实现者修复，增加地址序列化与失败证据保留测试。
3. 原生 `:minimal` 视图未暴露安装在用户目录中的 Codex 二进制，bubblewrap 无法执行；
   仅补入解析后的**确切二进制文件**只读权限，记录版本和文件摘要，不开放父目录或认证文件。

## 8. 模型预检脚本修复

[新运行说明](../../scripts/prechecks/model-protocol/README.md)。Kimi 实现，Codex 独立复核，
并在同一限定目录修复复核发现的问题。最终离线测试命令：

```sh
node --test --experimental-test-isolation=none scripts/prechecks/model-protocol/test/*.mjs
```

本轮 **24 项离线测试通过，新增真实模型协议探针调用 0 次**。覆盖跨场景/跨 run 的失败尝试
累计、多个进程共享账本的独占预留、预算耗尽后不调用、offline/live 账本隔离、唯一且不覆盖
的输出目录、剩余时限中止、缺凭据 BLOCKED、S3/S4 请求失败不误判、工具名/参数/配对校验、
非法调用不返回成功回执、CLI 场景顺序与退出码、错误/响应/汇总的注册假秘密脱敏。

这些是预检工具的工程验收，不是当前模型表现重新验收；旧 S4 FAIL 不变。
S3 的 PASS 仅表示观察完成，不代表 provider 已强制修复参数或宿主业务授权通过。
live 路径默认关闭，首次真实复跑仍需明确启用，不能从离线结果推导在线可靠性。
共享锁冲突或遗留锁会拒绝继续，不能自动删锁；预算不防外部篡改或另建账本规避。
原始实现、失败测试、修复后测试及复核报告分开保留于本轮私有目录。

最终复核位于 `model-protocol/REVIEW-by-codex.md`，最终测试原件为
