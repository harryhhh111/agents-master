# 持久协调层第一切片：规格与离线验收

日期：2026-10-16。依据 [第一轮方案](agent-system-first-slice-proposal.md)，
本规格细化会话、事务与恢复边界，不改变既有产品选择。

本轮交付是可运行的**假执行器联调**：不是主模型工具协议接线，不是已有 AgentCore 的持久化
改造完成，不是群聊 Web UI 上线。使用合成输入和新临时数据库；不访问真实项目、主人上下文
或生产数据库。真实 CLI、模型、扩展及个人记忆均不接线。

## 1. 数据归属与兼容

一个 SQLite 事务拥有者负责会话消息、用户输入 inbox、委派、运行、问题和回传 outbox。
现有主聊天消息表仍是唯一消息真相，不新建另一套竞争的 conversation 实现。
可拆分内部模块，但同一业务事务不能靠两个 store 分别 commit 模拟原子性。

- Conversation：稳定 ID、main/domain 类型、领域 Agent 与项目绑定。先只有 main 和一个工作领域群。
- Message：ID、conversationId、追加序号、真实作者、呈现类别、文本、关联委派/运行；模型 role
  与作者分开。客户端/模型文本不能决定可信作者或事件来源。
- 用户输入：由受信入口创建消息与 inbox，原子提交；呈现消息只保存，不自动变成输入事件。
- Assignment：一个输入事件最多一个委派；保存来源、目标、项目、目标/范围/完成标准、状态和版本。
- Run：一次尝试，保存 assignment/version、执行器标识、输入版本、启动/结束与结果；不是领域身份。
- Question：关联 assignment/version/run、正文、待答/已答/撤销及回答来源；等待时无活进程 Promise。
- Outbox：完成/失败/待答/取消/中断的耐久回执；不复用 domain-update 或 timer。

所有时间为严格 UTC ISO；排序用追加序号，不用可回填的时间戳。领域 context 默认只包含
本群截至锚点的消息及显式选定的项目背景，不自动转发主会话和全局主人背景。
上下文跨重试必须稳定：持久保存锚点、输入版本/检查点；新消息不会插入已经冻结的输入。

旧 API 默认仍作用于 main；新 API 显式指定会话。新会话读取、历史、锚点、inbox 领取、恢复
和回复写入均需按同一会话限定，不能只给消息加字段。旧 main-web/main-chat 本轮不自动启用
多会话协调；对新 schema 的读取至少不把领域消息混入 main。

## 2. 迁移规则

迁移是显式离线操作，不在普通 Web 启动时偷偷升级已有数据库。

1. 先检查 schema 版本与完整性；未知版本、半迁移、孤立引用、非 main 或矛盾关联一律拒绝。
2. 旧库只在全部消息确属单主会话时回填 main；无关联旧消息只能在整个旧库的单主会话前提下归属 main。
3. 迁移必须先产生一致的备份；不能直接复制仍可能有 WAL 写入的主文件。支持只在关闭/静止数据库
   上做离线操作，或使用 SQLite 一致备份机制。备份失败不迁移。
4. schema 版本和所有更改同事务提交；保留旧消息 ID、内容、追加序、inbox 关联和旧事件状态。
5. 重复执行不重复消息，不清空历史；迁移异常回滚。迁移后禁止旧版本程序连接写入：
   新实现检查版本；消息与 inbox 的 INSERT/UPDATE/DELETE 另以连接标记守卫拒绝旧连接误写，
   不仅检查消息来源。该标记是兼容保护，不是防御持有数据库写权限者的安全沙箱。
6. 回退只能在停服且确认新写入的保留策略后使用备份，本轮不提供自动破坏性回退。

测试只创建合成旧库和临时副本。生产数据库迁移、部署与服务重启需要另外授权。
迁移前停止其他读写者是调用方契约；实现仍需持有排他锁跨越备份与升级，竞争时失败而非忽略。
备份验收比较逻辑记录、完整性与外键，不要求 VACUUM 生成的备份文件字节相同。

## 3. 原子提交与幂等

| 操作 | 同一事务必须发生的事 |
| --- | --- |
| 用户输入 | 用户消息 + 对应 user-message inbox；同 ID 同内容返回原件，冲突内容拒绝 |
| 接收委派 | 验证可信来源与项目绑定 + Assignment + 群内派工消息 + 主会话接收回执 + 持久决定/返回值 |
| 启动领取 | 检查无同项目活动 run + queued → running/starting + 创建 Run；外部执行在事务外 |
| 回执落库 | 校验 run/版本 + 状态/结果或问题 + 群聊消息 + outbox；重复同回执返回原件 |
| 回答 | 检查问题待答及委派版本/状态 + 持久回答来源 + 关闭问题 + 委派重新排队；不扩大授权 |
| 主入口投递 | 核验回执当前性 + 主会话汇报消息 + delivered；重复返回已有消息 |

源事件而非文字是幂等槽位：同文字的新用户输入可以是新委托。重复工具决定不能因新参数而另建
第二份委派；参数冲突拒绝。提供给此离线切片的是受信宿主已确认的结构化决定，不做正则识别委托，
也不声称 schema 能证明用户意图。宿主动作允许列表仅包含假执行器的合成检查。

源消息必须真实存在、属于绑定会话且是用户输入。群聊派工/结果、模型自述及浏览器伪造作者
不能作为新的派工来源。关联项目/领域/返回会话均来自服务器绑定，不能接受任意路径。

## 4. 状态、等待与取消

Assignment：queued → running → completed / failed / waiting_input。
waiting_input 的有效回答 → queued，后续创建新 run；不假装恢复已结束进程。
queued/waiting_input 可在无需停止进程时取消；running 先 cancel_requested，收到可信停止确认
才 cancelled。失败或未知停止不能谎称已停。再次取消幂等。

Run：starting → running → succeeded / failed；取消中 cancel_requested → cancelled。
重启时尚无终态的 starting/running/cancel_requested → unknown，Assignment → interrupted。
新调度不自动重放未知尝试；已终态不因恢复再次执行。假执行器的停止确认也必须显式发生。
问题回执在同一事务内把 run 置为 succeeded（本次尝试成功产出问题）、Assignment 置为
waiting_input；不代表业务目标完成。重启不把该已终态 run 转为 unknown。

取消/状态变化带版本，迟到的旧运行结果保留为证据，但不能覆盖新状态、重新激活委派或被当作
新的完成汇报。过期问题、已取消任务的回答拒绝；同一回答重试返回已接受结果而不二次启动。
同项目只允许一个活动 run；等待输入的 run 已终态、不占后台执行槽，同项目其他 queued 工作也可继续。

## 5. 调度与交付

后台调度与前台短回合分离，前台不 await 执行器完成。每个会话的上下文有明确锚点，主入口
只有一个提交者。假前台必须在假执行器被人为阻塞期间完成另一条聊天回复，不仅仅返回接收 ACK。

完成、失败、待答等先保存结果和 outbox，不依赖浏览器在线。统一安全点调度先处理确定性的取消，
通常先用户输入；最多连续处理 3 个用户回合后，若有可交付回执，安排 1 次回传。该值是可配置
工程初值，不是用户产品偏好；用持续注入输入测试不饥饿，不承诺模型故障下的墙钟上限。
前台在途时结果只能排队，不改写已经发出的 context 或未配对工具记录。
主入口的聊天回复与 outbox 汇报由同一安全点调度者串行提交；在途回合期间产生的结果汇报，
其追加序必须晚于该回合回复。用户输入准入仍可随时发生，不受此输出串行规则阻塞。

回传失败保留 pending，可在后续安全点重试；不能因此阻止用户聊天或重跑后台。delivered 只表示
汇报已进目标历史，不是 SSE 到达或用户已读。旧问题/结果被新状态取代时，标明过期并跳过误导性
投递，不能把 outbox 清空当交付。遗留 domain-update/timer 完全不参与新流程。

## 6. 本轮验收与演示

提供只会创建新临时目录的演示命令，不接受生产 dataDirectory 或真实项目路径，不读取 `.env`。
展示主会话和群聊中的合成消息及状态，明确标注 FAKE。领域判断/主模型由确定性 stub 驱动，
接口允许后续替换；不把 stub 称作完成的领域 Agent 或新增通用 harness。

测试至少覆盖：

- 旧库正常迁移、备份、重复、混合会话拒绝、异常回滚及消息/关联完整性。
- 会话隔离、跨群锚点拒绝、时间回填仍按追加序、旧主聊不看到群聊。
- 可信输入与呈现分离、委派原子性、幂等重试/参数冲突、回执去重。
- 执行器阻塞时前台仍完成回复、同项目排队、持久问题及重启后回答一次。
- starting/running 崩溃不重放、终态待回传可恢复、取消竞争与迟到结果不覆盖。
- 持续用户输入中的有界投递、回传失败不阻塞聊天、遗留事件不被误领。
- 原有主聊天/登录测试及 typecheck 回归；浏览器群聊、真实模型/CLI 验收仍单独列为未完成。

实现与验收由两个独立 CLI 完成，保留原始产物。测试成功不授权部署、真实项目执行或 push。

## 7. 离线运行与接线限制

在仓库根目录运行（使用已安装的本地依赖，不联网安装）：

```sh
DOTENV_CONFIG_PATH=/dev/null node --import tsx scripts/smoke-coordination.ts
DOTENV_CONFIG_PATH=/dev/null npm test
DOTENV_CONFIG_PATH=/dev/null npm run typecheck
```

演示拒绝额外参数，仅在私有临时目录内创建合成数据库，退出时清理；打印 FAKE 主聊、群聊、
委派、问题、运行与回传状态。该命令不调用真实模型或 CLI，不使用项目 `.env`。
完整回归的旧入口导入链包含 `dotenv/config`，因此验证命令明确禁用其默认 `.env` 加载。

协调接口通过 `SQLiteMainInboxStore` 的显式 `coordination` 选项启用；未启用时现有服务不创建
协调 schema。`fresh` 只接受空库，`open` 只接受已知完整 schema，`migrate` 仅用于本轮经校验的
合成单主会话旧库及备份。当前固定 `fake-work` / `FAKE-project`，不是可供 Web 调用的通用派工 API。
迁移连接保持排他锁；迁移结束必须关闭该连接，再正常重新打开，不能把迁移句柄直接交给在线服务。
生产 composition root、主模型工具决定、AgentCore 领域判断、群聊 Web UI 和真实执行隔离仍待接线。
未来 schema 演进必须显式版本化，不能覆盖本版已创建的库或把测试用绑定当真实项目配置。
