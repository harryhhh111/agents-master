# Web 界面设计稿 v1：IM 形态聊天页（2026-10-21）

> 状态：**用户已确认**（2026-10-21，含三点修订：会话/版本切换守卫分离、异常独立警示、
> 卡片兜底定位）。作为预览通道界面改写的依据；稳定版界面不在本轮改动范围。
> 产品依据：`product-discovery-v0.md` §多事务响应与呈现形态——聊天 Tab 类似微信/Telegram，
> 主 Agent 一对一会话置顶且为唯一默认入口，每个长存领域子 Agent 对应一个群聊；
> 任务 Tab 类似游戏任务列表（本稿只做聊天 Tab，任务 Tab 另案）。

## 1. 现状与差距

现有预览页（`scripts/main-web.ts` 基页 + `src/main/coordination/web-page.ts` 补丁）：

- 单列布局，顶部两个按钮切换主聊/工作群，任务与待答问题收在一个 `<details>` 卡片盒里。
- 消息是简单列表行，角色只有文字前缀区分；无会话列表、无消息预览、无状态徽标。
- 页面由字符串替换补丁生成：每加一个结构特性都要再叠一层 replace，IM 化改造应当
  趁机把预览页改为独立模板（API 与交互守卫逻辑沿用，不重写）。

数据与交互已具备、设计稿直接复用的能力：会话切换与草稿保留、待确认/被拒提交提示、
SSE 增量、回答/取消控制、连接状态与重试。

## 2. 信息架构

```
聊天 Tab（本稿）
├── 会话列表（左栏）
│   ├── 主 Agent（置顶，一对一，默认入口）
│   └── 领域群聊（工作项目群 …；成员：我 + 主 Agent + 领域 Agent）
└── 会话区（右栏）
    ├── 会话头：名称、成员/范围说明、连接与回合状态
    ├── 消息流：气泡 + 内嵌任务卡/问题卡
    └── 输入区：草稿按会话保留；群内提示「默认发给领域 Agent，@main 呼叫主 Agent」
```

- 初版只有两个会话（主 Agent、工作项目群），但列表按"未来有多个领域群"设计。
- 任务 Tab 不进本稿；任务/问题在聊天 Tab 内以**内嵌卡片**呈现（见 §4），保证单一入口叙事完整。

## 3. 布局

**桌面端（≥768px）**：左栏固定 280px 会话列表；右栏会话区，消息列最大宽度 720px 居中。
**窄屏（<768px）**：单栏，默认消息流；左上角"‹ 会话"返回列表，列表项点击进入会话。
不设顶栏标题文字链；稳定/预览切换入口收进左栏底部（用户已在用的既有入口，位置变化需保留可达性）。

## 4. 组件规范

### 4.1 会话列表项

每行：名称 + 一行最后消息预览 + 右侧状态区。

- **主 Agent**：固定置顶，名称「主 Agent」；预览为最近一条消息摘要。
- **领域群聊**：名称（如「工作项目群」）+ 成员角注（3 人）；预览为最近一条消息摘要。
- 当前会话高亮。
- **会话切换与版本切换的守卫分开**（2026-10-21 用户确认）：
  - 主聊 ↔ 群聊**自由切换、不设阻塞**：草稿按会话保留，可随时来回查看；进行中的
    控制提交在后台继续执行，结果归回原会话显示。后台任务忙不成为用户不能聊天的理由。
  - 稳定版 ↔ 预览版、退出登录等**离开页面**的动作，才沿用离开前的未确认提交检查与
    丢弃确认。
- **状态徽标**：`待回答`（有待决问题，醒目色）、`进行中`（有 queued/running 任务，普通色）
  按优先级取一个；**异常独立显示**一个警示点（有提交"是否送达未知"或"已确定拒绝"时出现），
  与前者并列、不被遮住。列表项上不需要更复杂的状态系统。

### 4.2 消息流

- **气泡式**：我的消息靠右；主 Agent、领域 Agent 靠左，左侧带头像位（首字圆形块）与
  发送者名（群聊内必须，主聊可省略）。
- **角色配色**：用户 / 主 Agent / 领域 Agent 三色稳定不变；系统（runtime）消息不用气泡，
  居中灰色小字（如「已记录受限操作」）。
- **结构化消息保持语义**：dispatch（委派）、receipt（回执）、report（回传）在气泡左上角
  带类型标签（委派/回执/回传），颜色随发送者。不回退成纯文本流。
- 时间戳：消息间隙超过 5 分钟插入一条居中时间分隔，不给每条消息加时间。

### 4.3 内嵌任务卡 / 问题卡

取代现在的 `<details>` 卡片盒，卡片**内嵌在消息流中、与触发消息相邻**（dispatch 消息后
跟任务卡；waiting_input 回执后跟问题卡），同时会话头右侧保留一个「待办 n」汇总入口，
点击滚动定位到第一张未完成卡片。

- **任务卡**：目标摘要、状态（排队/进行中/待回答/已完成/已失败/已取消）、执行方式标识
  （真实 CLI/合成）、进行中的取消按钮（沿用控制提交流程与未确认提示）。
- **问题卡**：问题正文 + 回答输入框 + 提交按钮（沿用草稿保留、焦点恢复、幂等键）。
- 卡片状态随 SSE/轮询增量更新，不重绘整个消息流（沿用现有 snapshot 比对思路）。
- **兜底定位**：卡片的关联触发消息可能不在当前已加载的历史里（旧任务、分页外）。
  找不到关联消息时，未完成卡片仍要可见——归入会话区顶部的待办区常驻显示，
  待答问题的输入框与任务的取消入口始终可达，不因历史分页而消失。

### 4.4 输入区

- 沿用现有：Enter 发送、Shift+Enter 换行、发送失败行内重试、按会话草稿。
- 群聊占位文案：「发给工作项目群…（@main 呼叫主 Agent）」；主聊：「聊点什么…」。
- 回合进行中输入区不锁定（可继续排队发送），发送按钮旁显示回合状态点。

### 4.5 状态可见性

- 会话头状态条：连接中/已连接/断开重连；模型回合进行中（"正在思考…"）。
- 未确认/被拒提示保留为会话区顶部横幅，**明确区分两种文案**：「是否送达未知（可重试，
  相同提交不会重复执行）」与「已确定被拒绝（附原因）」；都不被轮询清空。
- 取消请求发出后任务卡显示「取消中…」，直到确认停止或判为未确认。

## 5. 视觉基调

浅色为主、单一强调色；圆角气泡、8px 间距网格；中文排版优先，等宽仅用于路径/代码片段。
不引入 UI 框架与构建链：预览页继续是单文件模板 + 原生 JS，样式内联 `<style>`。
（现有技术形态是有意选择——无构建步骤、release 打包直接复制；本稿不改变这一点。）

## 6. 非目标（本轮不做）

- 不改稳定版页面、不改任何 API/数据模型/存储。
- 不做任务 Tab、不做自由布局工作台、不做移动端原生手势（滑动返回等）。
- 不做消息搜索、引用回复、表情、附件。
- 预览/稳定切换的语义不变（数据独立、登录统一）。

## 7. 实现与验收要点

- 预览页改为独立模板文件（不再用字符串替换补丁叠加），复用现有 API 客户端与
  控制提交/草稿/状态轮询逻辑；稳定版基页保持不变。**只复用已有交互逻辑，
  不顺带抽象通用 UI 框架**（2026-10-21 用户确认）。
- 真实浏览器验收（Chromium）：登录 → 左栏主 Agent 置顶 → 主聊↔群聊自由来回切换、
  两侧草稿各自保留（无阻塞提示）→ 群内发委派 → 任务卡内嵌出现 → waiting_input
  问题卡可回答 → 完成后回执气泡带「回执」标签 → 带未确认提交时点版本切换被拦并提示。
- 现有 web/coordination 测试中的 DOM 断言按新结构更新；控制提交语义与版本切换守卫
  不允许退化（会话内切换守卫则按 §4.1 移除）。
- 窄屏用 375px 视口验收单栏切换。
